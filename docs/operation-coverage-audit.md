# Operation coverage audit

Baseline: `9526abb25e97f0c065d1565b06b696debf49781a` (Go 1.26+). This complete matrix was persisted **before source edits** and then updated with verified additions. The matrix's **Current recognition / Missing anchors preserve that pre-edit baseline**; the shared table and verification references record actual added coverage. `B-selected` identifies the now-delivered finite anchor batch, not the whole family or pending work; adjacent deferred anchors remain explicit. Families are investigation scopes, not detection promises. No percentage is implied.

## Evidence and interpretation

- **A**: baseline classified operation/attempt. **ID**: known API and source position but unclassified, usually an unresolved stdlib/interface site. **B**: worthwhile deterministic gap; selected/deferred distinguished below. **C**: behavioral obligation or pure/context computation, not an effect judgment.
- `internal/effects/effects.go`: exact package/receiver identities, argument-sensitive summaries and summary boundaries. `internal/analyzer/analyzer.go`: SSA operations, selected-source VTA, established/candidate propagation. `functionvalue.go`: closed singleton versus finite/open function alternatives. `details.go`, `effectview.go`, `audit.go`, `contracts.go`, `uncertainty.go`: source identities, projections, unresolved reasons and compatible implementations. `loading.go`: readonly package/workspace loading.
- `internal/output/` and `cmd/sidefx/main.go`: output/filter contracts. `argument_provenance.go` has a fixed narrow positional-role map, not taint/heap/alias analysis. `control_flow.go` attaches bounded structural context to existing sites, not a universal panic/defer inventory.
- Baseline evidence: `testdata/fixture`, `testdata/phase1`, exact sync/timer/signal/CertPool fixtures and CLI contract tests. An offline static-only 76-function probe confirmed gaps; phase-1 evidence was retained outside Git under `/tmp/sidefx-operation-audit.T6VMkp`. Tests are execution evidence only where explicitly recorded below.

## Recognition, propagation, retrieval and absence

Summary recognition is not end-to-end coverage through every call shape. Established source calls propagate into `effects`; finite function alternatives and VTA paths into `possible_effects`. Runtime conditions use ordinary operation effects plus uncertainty, **not** candidate effects. Unknown is internal and never a printed effect. Summary callbacks remain opaque; compatible implementations are not execution edges.

Normal effect view selects classified operations, including uncertain known effects. `-unresolved -api EXACT` retrieves known-identity/unclassified calls; normal `-api` can be empty for the same call. `unknown_api:false` does not classify effects. Zero-effect boundaries and native instructions not modeled as operations can be absent entirely. `-all` adds function inventory, not a universal call list. Ordinary function JSON lacks owner locations; details/audit are separate schemas. Legacy function-pair text omits uncertainty-only **and possible-only** functions. Empty output/false uncertainty never establishes safety or purity.

Default VTA is selected-source bounded; stdlib receiver discovery/general candidate-summary integration remains deferred. Exact summary support can work for direct or locally proven singleton calls yet be absent through a field-loaded interface. Argument roles are a separate narrow projection. Filters and site/edge limits reduce output, not loading/SSA cost.

### Post-review D01 correction
